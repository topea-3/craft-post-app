# デスクトップアプリ技術の候補調査・決定（TOP-7）

Craft Post App で採用するデスクトップアプリ技術の候補調査と比較結果、および採用技術の決定をまとめたドキュメントです。

---

## 1. 候補技術


| 候補            | 概要                                                                               |
| ------------- | -------------------------------------------------------------------------------- |
| **Electron**  | Chromium + Node.js をバンドル。Web 技術（HTML/CSS/JS）でデスクトップアプリを構築。                       |
| **Tauri**     | Rust バックエンド + 各 OS のネイティブ WebView（Windows: WebView2、macOS: WebKit）。フロントは Web 技術。 |
| **.NET MAUI** | Microsoft のクロスプラットフォーム UI フレームワーク。C# + XAML でネイティブに近い UI を構築。                    |


---

## 2. 比較観点ごとの整理

### 2.1 クロスプラットフォーム対応状況


| 技術            | Windows               | macOS                         | 備考                 |
| ------------- | --------------------- | ----------------------------- | ------------------ |
| **Electron**  | ✅ 対応                  | ✅ 対応                          | 同一バイナリ基盤で一貫した動作。   |
| **Tauri**     | ✅ 対応（WebView2）        | ✅ 対応（WebKit）                  | OS 標準 WebView を利用。 |
| **.NET MAUI** | ✅ 対応（WinUI 3, Win10+） | ✅ 対応（Mac Catalyst, macOS 11+） | ネイティブ UI に近い。      |


**要件・制約との対応**: 本プロジェクトは Windows 必須・macOS 要検討のため、いずれも要件を満たす。

---

### 2.2 パフォーマンスとメモリ消費


| 技術            | バイナリサイズ目安          | メモリ消費目安     | 起動時間目安    |
| ------------- | ------------------ | ----------- | --------- |
| **Electron**  | 80〜120 MB 程度       | 100 MB 以上   | 1〜2 秒程度   |
| **Tauri**     | 2.5〜3 MB 程度        | 30〜40 MB 程度 | 500 ms 未満 |
| **.NET MAUI** | ネイティブに近い（数十 MB 程度） | ネイティブに近い    | ネイティブに近い  |


Tauri が Electron よりメモリ・ディスクともに軽く、起動も速い。オフライン・ローカル主体の個人〜小規模利用では、軽量であることが運用面で有利。

---

### 2.3 エコシステム・ライブラリの充実度


| 技術            | エコシステム                                                             | 備考                                |
| ------------- | ------------------------------------------------------------------ | --------------------------------- |
| **Electron**  | 非常に充実。npm のほぼすべてが利用可能。                                             | 歴史が長く、情報・事例が豊富。                   |
| **Tauri**     | フロントは Web 標準 + npm。Rust 側は crates.io。プラグイン（Store, Updater 等）が公式提供。 | 成長中で、ローカルストア・アップデートなど必要な機能は揃っている。 |
| **.NET MAUI** | NuGet と .NET エコシステム。Windows/macOS 向けの成熟度は Windows が高い。             | C#/XAML に慣れたチーム向け。                |


要件（オフライン完結・ローカル保存・エクスポート/インポート・自動バックアップ検討）を満たすには、いずれも可能。Tauri は `tauri-plugin-store` でローカル永続化、`tauri-plugin-updater` でアップデートが公式サポートされている。

---

### 2.4 学習コストと既存スキルとの相性


| 技術            | 主な技術スタック                                                                 | 学習コストの目安                                     |
| ------------- | ------------------------------------------------------------------------ | -------------------------------------------- |
| **Electron**  | JavaScript/TypeScript, HTML, CSS, Node.js                                | Web 開発者なら低い。                                 |
| **Tauri**     | フロント: Web 技術（JS/TS, HTML, CSS）。バックエンド: Rust（必要に応じて。初回セットアップは Rust 環境が必要） | Web 開発者ならフロントはそのまま。Rust は「ネイティブ機能を触る時」のみでも可。 |
| **.NET MAUI** | C#, XAML, .NET                                                           | C#/XAML 経験者なら低い。Web のみの場合は高め。                |


フロントを Web 技術で統一したい場合は Electron か Tauri が相性が良い。

---

### 2.5 デプロイ・アップデートのしやすさ


| 技術            | 配布形態                                                  | 自動アップデート                                                |
| ------------- | ----------------------------------------------------- | ------------------------------------------------------- |
| **Electron**  | インストーラ / ポータブル。electron-builder 等で MSIX/EXE/dmg 等を生成。 | electron-updater 等で実装可能。実績多数。                           |
| **Tauri**     | インストーラ / ポータブル。Tauri ビルドで各 OS 向けパッケージを生成。             | 公式 `tauri-plugin-updater`。署名必須。静的 JSON またはアップデートサーバで配布。 |
| **.NET MAUI** | Windows: MSIX 等。macOS: Mac Catalyst で配布。              | Windows は .appinstaller + 公開 URL で自動更新可能。設定はやや手動になりがち。  |


要件では「アップデートの取得」は必要最小限とされているため、いずれも実現可能。Tauri は公式プラグインでアップデートが用意されている。

---

### 2.6 配布時の署名とコスト（Tauri を中心に）

「署名必須」には **2 種類** あり、費用の有無が異なる。


| 種類                    | 内容                                                    | 費用                         |
| --------------------- | ----------------------------------------------------- | -------------------------- |
| **Tauri Updater の署名** | アップデートパッケージの改ざん防止。`tauri signer generate` で自作の鍵ペアを使用。 | **追加費用なし**（自分で鍵を生成するだけ）    |
| **OS レベルのコード署名**      | インストーラ／実行ファイルを OS や SmartScreen 等に「信頼された発行元」として認識させる。 | **有料**（プラットフォームごとに証明書等が必要） |


**OS レベルで配布する場合の目安:**

- **Windows**: コード署名証明書（OV または EV）を CA から購入。OV でおおむね **年 $200〜300 程度**、EV は $300〜500+。未署名のまま配布すると SmartScreen の「不明な発行元」警告が継続する。Microsoft Trusted Signing は **$9.99〜99.99/月** のクラウド署名の選択肢。
- **macOS**: 配布 outside App Store では **Apple Developer Program（$99/年）** が事実上必須。証明書の作成・公証（notarization）は会員なら追加料金なし。未加入のまま配布すると「開発元を確認できない」等の警告が出る。

**結論**: Tauri の「アップデート用の署名」自体に追加費用はかからない。一方、**一般配布**（インストーラを不特定ユーザーに渡す）をスムーズに行うには、Windows は証明書購入、macOS は Developer Program 加入という **追加費用が発生しうる**。個人利用・社内配布のみであれば、未署名で配布し利用者に警告を了承してもらう運用も可能（要判断）。

Electron / .NET MAUI も、Windows・macOS で「信頼された発行元」として配布するなら同様の証明書・Developer Program が一般的に必要であり、Tauri だけが特別に高いわけではない。

## 3. 要件・制約との照らし合わせ

- **オフラインで完結**: いずれもオフライン動作可能。Tauri はバンドルが軽く、オフライン前提の端末にも向く。
- **データの保存場所（端末ローカル）**: Electron（Node の fs / ローカル DB）、Tauri（Store プラグイン・ファイル I/O）、MAUI（ローカルファイル／設定）でいずれも対応可能。
- **バックアップ（手動エクスポート・ローカル自動バックアップ検討）**: 各技術でファイル出力（JSON/CSV 等）を実装可能。
- **個人〜小規模・1 端末 1 ユーザー**: 大規模スケールは不要なため、軽量な Tauri の利点が生きる。

---

## 4. 採用技術の決定

### 決定: **Tauri** を採用する

### 理由（簡潔なメモ）

1. **パフォーマンス・メモリ**: バイナリ・メモリ・起動時間ともに軽く、オフライン・ローカル主体の利用形態に合う。
2. **クロスプラットフォーム**: Windows（WebView2）・macOS（WebKit）をサポートし、要件（Windows 必須・macOS 要検討）を満たす。
3. **技術スタック**: フロントは Web 技術のため、既存の Web スキルを活かしつつ、Rust は必要最小限（ビルド環境・プラグイン利用）から始められる。
4. **オフライン・ローカル**: 公式の Store プラグインでローカル永続化が用意されており、要件の「端末ローカル保存」と整合する。
5. **デプロイ・アップデート**: 公式 Updater プラグインで署名付き自動アップデートが可能（Updater の署名は自作鍵で無料）。※一般配布で OS レベルのコード署名を使う場合は別途費用あり（2.6 参照）。
6. **セキュリティ**: Rust ベースでデフォルトの権限が絞られており、ローカルで個人情報を扱う前提と相性が良い。
7. **Electron を選ばない理由**: 同じ Web 技術でも、本アプリの規模・利用想定では Electron の重さ（Chromium+Node のバンドル）は過剰と判断。Tauri で足りる。
8. **.NET MAUI を選ばない理由**: C#/XAML 中心のスタックとなり、Web 技術主体のチームでは学習コストが高くなる。また、デスクトップの自動アップデートやドキュメントの充実度は Tauri の方が扱いやすいと判断。

## 5. 次のアクション

- Tauri の開発環境構築（Rust ツールチェーン、Node、Tauri CLI）をプロジェクトで行う。
- 要件・制約ドキュメントの「macOS 対応要検討」の結論に合わせ、Tauri の macOS ビルド・配布方針を決める。
- **配布方針の決定**: 一般配布するか・社内/個人のみかで、OS レベルのコード署名（Windows 証明書・Apple Developer Program）に出す費用を検討する（2.6 参照）。
- アーキテクチャ設計タスクで、Tauri を前提にストレージ方式・バックアップ方式を具体化する。
