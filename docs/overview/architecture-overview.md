## 2. 各レイヤ・要素の説明

### 2.1 UI レイヤ（画面構成の大まかなブロック）

- **技術**: React + TypeScript。Tauri の WebView（Windows: WebView2、macOS: WebKit）上で動作する SPA。
- **主な画面ブロック**:
  - **住所録画面**: 住所録の一覧・検索・登録・編集。
  - **はがき送受信履歴画面**: 送受信履歴の一覧・フィルタ・住所録との紐付け。
  - **印刷プレビュー / 印刷実行**: 宛名面のプレビュー表示と印刷ダイアログ／PDF 出力の起点。
  - **設定・バックアップ／リストア**: アプリ設定、手動エクスポート／インポート、ローカル自動バックアップ設定（将来）など。

※ ナビゲーションや共通レイアウト（ヘッダ・サイドバー等）はアプリケーションロジック層と連携して実装する。

---

### 2.2 アプリケーションロジック層

- **React 側**: 画面状態、フォーム検証、ルーティング、Tauri コマンドの呼び出し、印刷用データの組み立て。
- **Tauri（Rust）側**: ウィンドウ・WebView の管理、ファイルシステム／ネイティブ API へのアクセス、SQLite への読み書き、コマンドとしてフロントに公開する API。
- **印刷レイアウト制御**: 宛名データとテンプレートを組み合わせ、@react-pdf/renderer に渡すまでの流れを制御するロジック（フロント中心で完結する想定）。

---

### 2.3 データ永続化層（ローカル DB など）

- **SQLite**: 住所録・はがき送受信履歴など、リレーショナルなデータの主体。Rust 側（例: rusqlite / sqlx）で保持し、Tauri コマンド経由でフロントから参照・更新する。1 ファイル = 1 DB のため、バックアップはファイルコピーやエクスポート（JSON/CSV）で対応可能。
- **tauri-plugin-store（任意）**: 設定やキー単位の小さいデータ用。必要に応じてアーキテクチャで併用を検討する。

---

### 2.4 印刷・レイアウトモジュール

- **@react-pdf/renderer**: はがきサイズ（100×148mm）に合わせた PDF を React コンポーネントから生成。宛名面の縦書き／横書き・余白・フォントはここで制御する。
- **コード内テンプレート**: 宛名レイアウトやデザイン面の雛形をコード（React コンポーネント＋スタイル）で定義する方針（TOP-10 で決定）。テンプレートファイルや DB 管理は今回の範囲では行わない想定。

---

### 2.5 将来的なクラウド連携ポイント（あれば）

- 要件・制約では **クラウドバックアップ・オンライン必須の利用は今回の範囲外**。図中では「将来拡張」として、データ永続化層やアプリケーションロジック層から **同期・バックアップ用 API** に接続する拡張ポイントを点線で示している。
- 将来、クラウド同期やオンラインバックアップを導入する場合は、このポイントにモジュールを追加する形で拡張する想定。
