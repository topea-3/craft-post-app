## SenderEntry 編集画面モック（v1）

- **画面ID**: `SEN003`
- **画面名**: 差出人編集

---

### 1. 画面レイアウト（フォーム＋紐づき管理）

- **上部エリア**
  - 左上: 画面タイトル「差出人編集」
  - タイトル直下: 対象の現在表示名（例: `山田 太郎・花子`）
    - `joinRecipients(primaryName, coRecipients)` の結果に準拠
  - 右上:
    - 「アーカイブ」メニュー／「戻る」リンク

- **フォーム本体**
  - 作成画面（`SEN002`）と同じ項目構成
  - 初期値として既存の `SenderEntry` の値を反映

#### 1.1 差出人入力（作成画面との差分）

- 連名の行追加／削除は `coRecipients` の **0〜4 件**の範囲に制限
- `SenderLabel.value` は編集可能とする（v1: UI 上で有効行＝`archivedAt` 未設定同士の範囲で一意をアプリ側でチェック）

---

### 2. 紐づき宛名の管理（SenderAddressLink）

- **セクションタイトル**: 紐づき宛名
  - 説明文: 「この差出人として印字する宛名（住所録）を管理します。宛名 1 件に紐づく差出人は有効データの範囲では高々 1 人です。」

#### 2.1 現在の紐づき一覧

- 表（またはカード）で表示
  - 行クリック: （任意）宛名詳細 `AddressEntry` へ遷移
  - 各行に「解除」ボタン（または操作メニュー）
    - 実行 → `SenderAddressLink`（該当 sender_entry_id/address_entry_id）の削除

表示項目案:

- 宛名表示名（`AddressEntry.primaryName.display` + 連名 `joinRecipients` + 敬称を表示するなら `AddressEntry` 側の表現に従う）
- 郵便番号 / 住所（`Address`）の 1 行表現

#### 2.2 紐づけ追加（宛名選択）

- 「紐づけ追加」ボタン
  - クリック → `AddressEntry` の選択モーダル（もしくはサブ画面）を開く

宛名を選択したときの挙動:

- 対象 `addressEntryId` が **すでに別の `SenderEntry` に紐づいている**場合
  - 確認ダイアログで置き換え確認
    - 「この宛名はすでに別の差出人に紐づいています。置き換えますか？」
  - OKの場合:
    - 既存リンクを削除
    - 新しいリンクを追加（この画面の `SenderEntry` へ紐づけ）
  - キャンセルの場合:
    - リンク追加は行わない

---

### 3. ボタン・アクション

- **画面下部ボタンエリア**
  - 左: 「キャンセル」ボタン（セカンダリ）
    - クリック → 変更がある場合は確認ダイアログ
    - 確認後 → 詳細画面（`SEN004`）または一覧画面（`SEN001`）へ戻る設計

  - 中央左寄せ: 「アーカイブ」ボタン（またはメニュー）
    - クリック → 確認ダイアログ
      - 「この差出人をアーカイブしますか？一覧からは非表示になりますが、データは保持されます。」
    - 確認後 → `archivedAt` を設定してアーカイブし、紐づく宛名とのリンクを削除（`updatedAt` は変えない）
    - 成功後 → 一覧画面（`SEN001`）へ遷移

  - 右: 「保存」ボタン（Primary）
    - クリック → バリデーション
    - 問題なければ `UpdateSenderEntry` を実行
    - 成功後の遷移先候補:
      - A: 詳細画面（`SEN004`）
      - B: 一覧画面（`SEN001`）

---

### 4. バリデーションとエラー表示

- 作成画面（`SEN002`）と同じ必須・形式制約に従う
- さらに、紐づき追加時の置き換え確認（置き換えキャンセル時はリンクを変更しない）を UI で担保
