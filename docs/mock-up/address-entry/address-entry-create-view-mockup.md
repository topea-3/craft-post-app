## AddressEntry 作成画面モック（v1）

- **画面ID**: `ADDR002`
- **画面名**: 住所録新規作成

---

### 1. 画面レイアウト（フォーム）

- **上部エリア**
  - 左上: 画面タイトル「住所録新規作成」
  - 右上: 「キャンセル」リンク（一覧へ戻る）
- **フォーム本体**

#### 1.1 宛先情報（氏名・連名・敬称）

| 項目名   | UI コンポーネント     | 対応ドメイン                            | 備考                                       |
|----------|------------------------|-----------------------------------------|--------------------------------------------|
| 姓       | テキスト入力          | `primaryName.last`                     | **必須**                                   |
| 名       | テキスト入力          | `primaryName.first`                    | **必須**                                   |
| カナ（姓）| テキスト入力          | `primaryName.kanaLast`                 | 任意（将来のソート等に利用）               |
| カナ（名）| テキスト入力          | `primaryName.kanaFirst`                | 任意                                       |
| 連名     | 繰り返し行＋テキスト入力 | `coRecipients: PersonName.full[]`     | 行追加／削除ボタン。0 件〜 3 件。           |
| 敬称     | セレクトボックス      | `Honorific`                            | プリセット: `様`, `御中`, `ご家族様`, `なし` |


#### 1.2 住所情報


| 項目名      | UI コンポーネント  | 対応ドメイン               | 備考                          |
| -------- | ----------- | -------------------- | --------------------------- |
| 郵便番号     | テキスト入力（7 桁） | `PostalCode.value`   | **必須**。`1234567` 形式。半角数字のみ。 |
| 都道府県     | セレクトボックス    | `Address.prefecture` | **必須**。プリセットから選択。           |
| 市区町村     | テキスト入力      | `Address.city`       | **必須**。例: `渋谷区`             |
| 町名・番地    | テキスト入力      | `Address.street`     | **必須**。例: `神南 1-1-1`        |
| 建物名・部屋番号 | テキスト入力      | `Address.building`   | 任意。例: `○○ビル 3F`             |


#### 1.3 メモ


| 項目名 | UI コンポーネント | 対応ドメイン      | 備考                 |
| --- | ---------- | ----------- | ------------------ |
| メモ  | テキストエリア    | `Memo.text` | 最大 1000 文字。自由記述。 |

#### 1.4 差出人の紐づき（宛名側）

- **目的**
  - この `AddressEntry`（宛名）に対して、印字に使う差出人（`SenderEntry`）を `SenderAddressLink` で関連づける。
  - v1 では「宛名 1 件に対して、紐づく差出人は有効データの範囲では高々 1 人」として扱う。

- **UI コンポーネント案**
  - 差出人選択（`archived = false` の `SenderEntry` から選択）
    - 選択 UI: セレクトボックス or カード一覧
    - 表示: `SenderLabel.value`
  - 「未設定」も選べる（この場合は `SenderAddressLink` を作らない）

- **保存時の挙動**
  - `CreateAddressEntry` 成功後、作成された `AddressEntry.id` を使って `SenderAddressLink` を作成（または未設定なら作成しない）。


---

### 2. ボタン・アクション

- **画面下部ボタンエリア**
  - 左: 「キャンセル」ボタン（セカンダリ）
    - クリック → 確認ダイアログ（編集中の場合）
      - 「編集中の内容を破棄して一覧に戻ります。よろしいですか？」
    - 確認後 → 一覧画面（`ADDR001`）へ遷移。
  - 右: 「保存」ボタン（Primary）
    - クリック → バリデーション
    - 問題なければ `CreateAddressEntry` を実行。
    - 成功後の遷移先候補:
      - パターン A: 一覧画面（`ADDR001`）へ戻る。
      - パターン B: 作成したエントリの詳細画面（`ADDR004`）へ遷移。

---

### 3. バリデーションとエラー表示

- **必須項目**
  - 主たる氏名（姓・名）、郵便番号、都道府県、市区町村、町名・番地。
  - エラー時は該当フィールド下に赤文字でメッセージ表示。
- **郵便番号形式**
  - 半角数字のみ／7 桁チェック。
  - 不正な場合: 「郵便番号は 7 桁の半角数字で入力してください。」
- **文字数制限**
  - 氏名・住所各フィールド: 128〜256 文字上限を想定。
  - メモ: 1000 文字程度。
- **敬称**
  - セレクトボックスでプリセット以外を選べないようにする（ドメイン側でもバリデーション）。

---

### 4. UX メモ

- **入力補助**
  - 郵便番号入力後に住所自動補完を行うかは別途検討（v1 では必須ではない）。
  - 連名は初期状態で 0 行とし、「＋連名を追加」リンクで行追加。
- **画面共通化**
  - 編集画面（`ADDR003`）とフォームコンポーネントを共通化できる前提で設計する。
